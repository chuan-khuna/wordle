1. What's in the repo

There are four programs. They share one set of word lists and one folder of precomputed files:

Python package

packages/wordle/: the game engine, the Solver, the terminal game and every just precompute-* command.

gpui desktop app

app/wordle-gpui/: the same game and Solver in Rust, with a window. It also runs the precompute, much faster.

Web backend

app/backend/: FastAPI on port 8000. It reuses the Python package and reads precompute-cache/.

Web frontend

app/frontend/: Next.js on port 3000. It sends /api calls on to the backend.

Every command lives in the justfile at the repo root. Run just to list them.

3. First setup

git clone <repo-url> wordle
cd wordle
uv sync                          # Python workspace: the wordle package and pytest
(cd app/frontend && bun install) # web frontend packages
just wordle                      # play once in the terminal, to check Python works

The backend is a uv project of its own (app/backend/pyproject.toml). uv run syncs it the first time you run just backend or just web, so it needs no step here. The first cargo build of the desktop app compiles gpui, which takes a few minutes.

4. How precompute-cache/ is laid out

The Solver never works out Feedback while it runs: it looks each one up in matrices that were computed ahead of time. All precomputed data goes in one folder at the repo root, precompute-cache/. Every tool reads and writes the same files there: the Python commands, the gpui app and the backend.

precompute-cache/                  # gitignored
├── feedback/                      # the Feedback matrices (~40 MB, rebuilt in about a second)
│   ├── guesses_vs_answers.npy     # 14,855 Guesses × 2,315 Answers, one u8 per pair
│   └── answers_vs_answers.npy     # 2,315 × 2,315: the Answer rows only
├── guess-counts/                  # the Guess Count Matrix of each of the 8 Strategies (~175 MB)
│   ├── manifest.json              # format version, word lists, Strategy definitions, which tool wrote it
│   ├── summary.json               # every Opener ranked per Strategy: average, Losses, distribution
│   ├── bits/                      # Ranking = Expected Information
│   │   ├── answers-candidates.npy # <pool>-<scope>.npy: rows = Openers, columns = Answers
│   │   ├── answers-candidates.ranking.csv
│   │   └── …                      # answers-all, guesses-candidates, guesses-all
│   └── expected/                  # Ranking = Expected Candidates, the same four files
└── benchmark/                     # what the website's Benchmark and Opener pages show (~100 KB)
    ├── benchmark.json             # each Strategy played from its own best Opener
    └── openers.json               # the 500 best first Guesses by Expected Information

What each file holds

  • A Feedback matrix cell is one Guess scored against one Answer. The five Marks are read as base-3 digits (Absent 0, Present 1, Correct 2), so a Win is 242. Rows and columns are in sorted word order. A Solver turn only counts cell values over the columns of the Candidates that are left.
  • A Guess Count Matrix cell is how many Guesses a Strategy needs to Win an Answer from that row's Opener. A 7 or more counts as a Loss, and 13 means the safety limit was hit. A row of zeros has not been filled yet. Rows are written whole, so a run that stops halfway can be resumed by either tool.
  • The eight Strategies are every combination of three choices: Ranking (bits or expected), Guess Pool (answers or guesses) and Search Scope (candidates or all). An Answer List matrix has 2,315 rows and a Guess List matrix has 14,855.
  • The format is .npy: a 128-byte header, then the raw cells. numpy memory-maps it and Rust writes it directly, and the tests pin the same bytes from both tools.

Who needs what

FolderRead byIf it is missing
feedback/The Solver in every programThe backend fails to start. The Python commands build it first. The gpui app asks you to run Precompute matrices…
guess-counts/summary.jsonThe backend's /api/guess-counts and the gpui Solver panel's Guess DistributionOnly those features are missing. Everything else works.
benchmark/The backend's /api/benchmark and /api/openersOnly those endpoints fail

The backup in git. precompute-cache/ is gitignored, but an xz copy of the finished guess-counts/ and benchmark/ folders is committed in data/precompute/ (about 29 MB). just restore-cache unpacks it and just backup-cache refreshes it. feedback/ is left out of the backup because it rebuilds in about a second.

5. Running the precompute: Python or Rust

The quick way: restore, don't recompute

You don't need to recompute the Guess Count Matrices on a new machine:

just precompute --threads 8 --yes  # Feedback matrices, about a second
just restore-cache --yes           # guess-counts/ and benchmark/ from data/precompute/

Computing it yourself

Python and Rust write the same files, byte for byte. The only difference is the tool field in manifest.json. So you can stop a run in one tool and resume it in the other. What differs is speed:

StepPython (just …)Rust (gpui app menu)
Feedback matricesjust precompute: about 1 sPrecompute matrices…: about 1 s
Guess Count Matrices, all 8 Strategiesjust precompute-guess-counts: many hours. The two Guess List, All words Strategies take 5 to 9 s per Opener on one thread, and threads help only about 3× because of the GIL.Precompute guess counts…: about half an hour on 8 threads
Benchmark and Opener leaderboardjust precompute-benchmark: about 12 s on 8 threadsPrecompute benchmark: under 1 s. It also runs by itself when a guess-counts run finishes.

One measured comparison: 76 sample rows over the eight Strategies took 65.6 s in Python and 9.0 s in Rust.

Recommended: the Rust gpui app suggested

just wordle-gpui                   # cargo run --release in app/wordle-gpui
  1. Open the menu (the hamburger in the title bar) or the command palette (⌘P, or Ctrl+P on other systems).
  2. Run Precompute matrices… and choose a thread count. This writes feedback/.
  3. Run Precompute guess counts…. Choose a thread count (it starts on the most your machine has cores for) and the Strategies (all are on by default), then press Enter. The board is replaced by a progress view with a bar per Strategy, the rate, the time left and a log. Stop keeps every finished row, and running the command again later picks up where it stopped.
  4. When every row is filled, the same run goes on to the Benchmark and writes benchmark/benchmark.json and openers.json. To redo only the Benchmark, run Precompute benchmark.
  5. Press Back to game, Enter or Escape to close the view.

The Python commands

Each one asks for a thread count, and asks before it overwrites anything. Flags skip the questions:

just precompute --threads 8 --yes
just precompute-guess-counts --threads 8 --strategy bits-guesses-all --opener salet  # a quick check
just precompute-guess-counts --threads 8 --yes      # resume every Strategy (--fresh starts over)
just precompute-benchmark --threads 8 --yes

After a full run, use just backup-cache to refresh the committed copy in data/precompute/. It refuses if a matrix is unfinished.

6. Starting the web app

First make sure precompute-cache/feedback/ exists (step 5); the backend won't start without it. Then:

just web                           # backend on :8000 and frontend on :3000; Ctrl-C stops both

Open http://localhost:3000. The frontend rewrites /api/* to the backend, so the browser only ever talks to port 3000.

To run the two separately, for example to restart one or change a port:

just backend                       # FastAPI on http://127.0.0.1:8000; extra args go to uvicorn, e.g. --reload
just frontend                      # Next.js dev server on http://localhost:3000; e.g. --port 3001
BACKEND_URL=http://127.0.0.1:8001 just frontend   # if the backend runs elsewhere

The Benchmark, Opener leaderboard and Opener Distribution pages need benchmark/ and guess-counts/summary.json. Without them, the rest of the site still works.

7. Running the tests

just test                          # Python package (pytest)
just test-gpui                     # gpui app (cargo test)
just test-backend                  # web backend (pytest)
(cd app/frontend && bun test && bun run typecheck)

Several Rust tests compare the app's output with Python's, byte for byte, whenever the Python files are there: the Feedback matrices, the Guess Count rows and summary, and the Benchmark. To point them at a folder Python wrote, set WORDLE_PYTHON_GUESS_COUNTS or WORDLE_PYTHON_BENCHMARK.

8. When something goes wrong

  • The backend says the matrices are missing: run just precompute.
  • "manifest.json was written by format version 1": an old Guess Count folder. Run just migrate-guess-counts.
  • "Can't resume <id>": the matrix doesn't match the current word lists or Strategy definitions. Restore it from the backup, or start it over (--fresh, or delete precompute-cache/guess-counts/).
  • Port 3000 or 8000 is already in use: pass --port to just frontend or just backend, and set BACKEND_URL to match.
