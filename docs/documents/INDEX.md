# Implementation documents

How this project is built. Domain terms are defined in [GLOSSARY.md](../../GLOSSARY.md).

- [Architecture](architecture.md): the uv workspace, the `wordle` package's modules and layers, how to run, build and test it.
- [Feedback scoring](feedback-scoring.md): the two-pass rule that gives each letter its Mark, with repeated-letter examples.
- [Game and State](game-and-state.md): the `Game`, `Guess` and `State` classes, guess validation, Seeds, the Guess Limit, Win and Loss, and trying words after a Game ends.
- [Terminal UI](terminal-ui.md): the questionary menus, the rich board and keyboard, the share grid, replaying a Game by its Seed, and how to drive the UI from a script.
- [gpui desktop app](gpui-app.md): the Rust + gpui window in `app/wordle-gpui/`: its module layout (engine, solver, overlays, ui), the Solver panel (Words, Search and Rank by settings naming one of the four Strategies, with its Feedback Split chart, and before the first Guess each Opener's Average Guess Count, Losses and Guess Distribution chart from the Guess Count Matrix summary, or a note saying why there is none), Solver mode for a Wordle played elsewhere (Feedback clicked in by hand), the settings menu and command palette, **Precompute guess counts…** (the Rust tree play and Guess Count Matrix build, its picker, status bar progress and stop), live hints, the sidebar's Oxford dictionary lookups, how to run it with `just`, and how its Seeds match the Python game.
- [Feedback matrices](feedback-matrices.md): the precomputed Answer × Answer and Guess × Answer Feedback matrices, their cell encoding, why `.npy`, and how Python and the gpui app regenerate them.
- [Solver Strategy](solver-strategy.md): how the Solver scores Guesses by Expected Information and Expected Candidates from the matrices, its pool and scope options, the tree play that gives every Answer's Guess Count with its shared next-Guess cache, how it differs from the reference project, and the Answers (with Seeds) a Candidates-only search fails on.
- [`.npy` files in Python and Rust](npy-in-python-and-rust.md): which tool writes which matrix, one file byte by byte (the 128-byte header, row and column order, example cells with words), how numpy and the gpui app write and read it, the differences and the tests that pin the same bytes, and the contract both Guess Count Matrix writers (Python and the gpui app) follow, including numpy's pairwise summation for `bits`.
- [Guess Count Matrix](guess-count-matrix.md): the Guesses every Opener needs for every Answer under each Strategy: the `.npy` matrices, `manifest.json` (word lists, Strategy definitions), the compact `summary.json` (ranking, Losses, Guess Distribution) and `<id>.ranking.csv`, the build function, its worker threads (one writer thread, shared cache, byte-identical results) and tqdm progress bars, resuming (zero rows only, whole-row commits, flushes, Ctrl+C, the manifest check), `just precompute-guess-counts` with its thread question, resume / start over / cancel question, `--threads`, `--yes` and `--fresh`, cost figures with the measured (GIL-limited) speed-up from threads; the gpui app's Rust build of the same files and its measured cost.
- [Web backend](web-backend.md): the FastAPI project in `app/backend/`, which reuses the `wordle` package's engine through a uv path dependency: its layout (`main.py`, `routers/`, shared `common.py`, the `WebSolver` wrapper), the precompute command and its Feedback matrices, the precomputed Benchmark and Opener leaderboard (four Strategies, results), the JSON API (endpoints, Marks as digit strings, 400 and 503 errors), and how to run and test it.
- [Web frontend](web-frontend.md): the Next.js app in `app/frontend/` (App Router, TypeScript, Tailwind, bun with a 7-day minimum release age): its layout, `just frontend` and `just web`, the `/api` rewrite to `BACKEND_URL`, the ten gpui themes as CSS variables and Tailwind colours with a no-flash dropdown menu saved in `localStorage`; the editorial design tokens (fonts, type scale, space, measure, rules, focus) in `tokens.css`; and the one Series (the home page) with its two Parts and the Articles pipeline (MDX with KaTeX, frontmatter, Parts, two-digit Article numbers, Prerequisites, backlinks, prev/next, video timestamps, build-time validation) and the site-wide sidebar (title, Articles grouped by Part, theme menu; a top bar with a menu button on phones), the Article layout with a margin for `<MarginNote>`s (a container query), and the `<Term>` glossary component (a shadcn Tooltip); the shadcn/ui setup (`components.json`, `components/ui/`, the pinned CLI, how its variables map onto the tokens, how to add a component) and the icon theme menu; and Code blocks (build-time Shiki highlighting in theme roles, title, line highlights, copy button), and the Widgets (with their Wordle-style `WordRow` word input and `StateBoard` State input) (Feedback scorer, Candidate filter, Feedback Split explorer, Step-through Game, Opener table, Benchmark chart): props, URL params that override them, `id` namespacing, the TypeScript Feedback port, and the TanStack Charts setup (theme-role colours, SSR).
