# Implementation documents

How this project is built. Domain terms are defined in [GLOSSARY.md](../../GLOSSARY.md).

- [Architecture](architecture.md): the uv workspace, the `wordle` package's modules and layers, how to run, build and test it.
- [Feedback scoring](feedback-scoring.md): the two-pass rule that gives each letter its Mark, with repeated-letter examples.
- [Game and State](game-and-state.md): the `Game`, `Guess` and `State` classes, guess validation, Seeds, the Guess Limit, Win and Loss, and trying words after a Game ends.
- [Terminal UI](terminal-ui.md): the questionary menus, the rich board and keyboard, the share grid, replaying a Game by its Seed, and how to drive the UI from a script.
- [gpui desktop app](gpui-app.md): the Rust + gpui window in `app/wordle-gpui/`: its module layout (engine, solver, overlays, ui), the Solver panel (Guess Pool, Search Scope and Ranking settings naming one of the eight Strategies, the Opener ranked over the whole Guess Pool, with its Feedback Split chart, and before the first Guess each Opener's Average Guess Count, Losses and Guess Distribution chart from the version 2 Guess Count Matrix summary, or a note saying why there is none), Solver mode for a Wordle played elsewhere (Feedback clicked in by hand), the settings menu and command palette, **Precompute guess counts…** (the Rust tree play and format version 2 Guess Count Matrix build of the eight Strategies into the shared `precompute-cache/guess-counts/`, byte for byte as Python's; a version 1 folder refused, pointing at `just migrate-guess-counts`; its picker and stop), the precompute view that replaces the board while either precompute runs (overall and per-item progress with rate and time left, a bounded log, Stop and Back to game; nothing in the status bar), live hints, the sidebar's Oxford dictionary lookups, how to run it with `just`, and how its Seeds match the Python game.
- [Feedback matrices](feedback-matrices.md): the precomputed Answer × Answer and Guess × Answer Feedback matrices, their cell encoding, why `.npy`, and how Python and the gpui app regenerate them.
- [Solver Strategy](solver-strategy.md): how the Solver scores Guesses by Expected Information and Expected Candidates from the matrices, its Guess Pool, Search Scope and Ranking options, the eight Strategies (ids, paths, display names; the Opener ranked over the whole Guess Pool), the tree play that gives every Answer's Guess Count with its shared next-Guess cache, how it differs from the reference project, and the Answers (with Seeds) a Candidates-only search fails on.
- [`.npy` files in Python and Rust](npy-in-python-and-rust.md): what the `.npy` format is and why it suits a matrix filled in place, which tool writes which matrix (both into the same shared folders), one file byte by byte (the 128-byte header, row and column order, example cells with words, a Loss kept at its real Guess Count), how numpy and the gpui app write and read it, the differences and the tests that pin the same bytes, and the contract both Guess Count Matrix writers (Python and the gpui app) follow (format version 2), including numpy's pairwise summation for `bits`.
- [Guess Count Matrix](guess-count-matrix.md): the Guesses every Opener needs for every Answer under each of the eight Strategies: the version 2 layout (`bits/` and `expected/` folders of `<pool>-<scope>.npy`, one row per Guess Pool word), `manifest.json` (format version 2: word lists per Guess Pool, Strategy definitions and paths; a version 1 folder is a mismatch pointing at `just migrate-guess-counts`), migrating a version 1 folder (`just migrate-guess-counts`: rows copied, Answer List rows sliced out, zero rows kept, version 1 files removed last), the compact `summary.json` (ranking, Losses, Guess Distribution) and `<ranking>/<pool>-<scope>.ranking.csv`, the build function, its worker threads (one writer thread, shared cache, byte-identical results) and tqdm progress bars, resuming (zero rows only, whole-row commits, flushes, Ctrl+C, the manifest check), `just precompute-guess-counts` with its thread question, resume / start over / cancel question, `--threads`, `--yes` and `--fresh`, cost figures with the measured (GIL-limited) speed-up from threads; the gpui app's Rust build of the same version 2 files (tested both ways against Python's) and its measured cost (including filling the real folder's two `answers-all` matrices); Results: the top 5 Openers of each of the eight Strategies from the full real matrices, and how Answer List with All words compares with Guess List with All words.
- [Precompute backup](precompute-backup.md): `just backup-cache` and `just restore-cache` (`src/precompute_backup.py`), which keep an xz copy of `precompute-cache/` (all but the Feedback matrices, and only finished Guess Count Matrices) in the committed `data/precompute/`, subfolders included (`guess-counts/bits/`, `expected/`), and restore a version 1 backup for the migration.
- [Web backend](web-backend.md): the FastAPI project in `app/backend/`, which reuses the `wordle` package's engine through a uv path dependency: its layout (`main.py`, `routers/`, shared `common.py`, the `WebSolver` wrapper), the precomputed files it reads (Feedback matrices, and the Benchmark and Opener leaderboard that the package's `just precompute-benchmark` writes: eight Strategies, results), the JSON API (endpoints, including `GET /api/guess-counts` for any of the eight Strategy ids (default `bits-guesses-all`) from the optional version 2 Guess Count Matrix summary, gzipped, and `GET /api/solve` with its Opener ranked over the whole Guess Pool; Marks as digit strings, 400 and 503 errors), and how to run and test it.
- [Web frontend](web-frontend.md): the Next.js app in `app/frontend/` (App Router, TypeScript, Tailwind, bun with a 7-day minimum release age): its layout, `just frontend` and `just web`, `bun run screenshot` (Playwright shots of each page's top and every Widget, by theme and width), the `/api` rewrite to `BACKEND_URL`, the ten gpui themes as CSS variables and Tailwind colours with a no-flash dropdown menu saved in `localStorage` (no "system" option;
