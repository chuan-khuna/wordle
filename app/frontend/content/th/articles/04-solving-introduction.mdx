ก่อน Guess แรก Answer อาจเป็นคำใดก็ได้ใน 2,315 คำ หลังจากนั้นคุณจะได้ Feedback หนึ่งในไม่เกิน 243 แบบ อะไรทำให้ Guess แรกอันหนึ่งดีกว่าอีกอัน?

ลองคิดว่าหลังได้คำตอบกลับครั้งแรก คุณอยากถืออะไรอยู่ในมือ คือ Answer ที่เป็นไปได้ให้น้อยที่สุดเท่าที่ทำได้ คำที่ยังเป็น Answer ได้คือ <Term>Candidate</Term> และทั้งหมดรวมกันคือ <Term>Candidate Set</Term> Article ถัดไปจะอธิบายเรื่องนี้ให้ชัด

Guess ไม่ได้เลือกว่าคุณจะได้ Feedback อะไร Answer เป็นคนเลือก สิ่งที่ Guess เลือกคือวิธีแบ่ง 2,315 คำตามคำตอบกลับนั้น Answer ทุกคำที่เป็นไปได้ให้ Feedback แบบใดแบบหนึ่ง Guess จึงแบ่งทุกคำออกเป็นกลุ่ม หนึ่งกลุ่มต่อหนึ่ง Feedback การแบ่งนี้คือ <Term>Feedback Split</Term>

ลองเทียบสอง Guess <Word>crane</Word> แบ่ง 2,315 คำเป็น 142 กลุ่ม กลุ่มใหญ่สุดคือกลุ่มที่ไม่มี <Letter>c</Letter>, <Letter>r</Letter>, <Letter>a</Letter>, <Letter>n</Letter> หรือ <Letter>e</Letter> เลย มี 263 คำ ส่วน <Word>fuzzy</Word> แบ่งได้แค่ 34 กลุ่ม และกลุ่มใหญ่สุดของมันคือกลุ่มที่ไม่มีตัวอักษรของมันเลย มี 1,352 คำ คำตอบกลับของ <Word>crane</Word> เหลือคำให้คุณน้อยกว่าคำตอบกลับของ <Word>fuzzy</Word> มากเมื่อเฉลี่ย

Guess ที่ดีจึงแบ่งได้หลายกลุ่ม และแต่ละกลุ่มเล็กและเท่า ๆ กัน ทีนี้มานับกัน

## สองวิธีนับ

เรียกจำนวน Candidate ว่า $N$ Guess แบ่งมันเป็นกลุ่มขนาด $n_1, n_2, \ldots$ หนึ่งกลุ่มต่อหนึ่ง Feedback ที่ Guess นั้นอาจได้ กลุ่มของ Feedback ที่ $i$ จะเกิดขึ้นด้วยความน่าจะเป็น

$$
p_i = \frac{n_i}{N}
$$

เพราะถ้า Candidate ทุกคำมีโอกาสเป็น Answer เท่ากัน โอกาสที่จะตกในกลุ่มหนึ่งก็คือสัดส่วนของคำในกลุ่มนั้น

นี่คือแนวคิดสำคัญ **เราตัดสิน Guess จากสิ่งที่เหลืออยู่หลังได้ Feedback หนึ่งครั้ง โดยเฉลี่ยตามการแบ่ง** แต่ละกลุ่มมีคะแนน และค่าเฉลี่ยถ่วงน้ำหนักด้วย $p_i$ คะแนนของกลุ่มมีสองแบบที่เป็นธรรมชาติ

แบบแรกคือขนาดของกลุ่ม $n_i$ หรือจำนวน Candidate ที่เหลือ เมื่อเฉลี่ยแล้วจะได้ <Term>Expected Candidates</Term> คือจำนวน Answer ที่เป็นไปได้ซึ่งเราคาดว่าจะเหลือ ยิ่งน้อยยิ่งดี

$$
\mathbb{E}[\text{left}] = \sum_i p_i \, n_i = \frac{1}{N}\sum_i n_i^2
$$

แบบที่สองคือกลุ่มนั้นลด Candidate Set ลงกี่เท่า กลุ่มขนาด $n_i$ จาก $N$ ลดเซตลงด้วยตัวคูณ $N / n_i$ และเรานับเป็นจำนวนครั้งที่หารครึ่ง ซึ่งเรียกว่าบิต กลุ่มที่เป็นครึ่งหนึ่งของคำทั้งหมดมีค่าหนึ่งบิต กลุ่มที่เป็นหนึ่งในสี่มีค่าสองบิต เมื่อเฉลี่ยแล้วจะได้ <Term>Expected Information</Term> ยิ่งมากยิ่งดี

$$
\mathbb{E}[\text{bits}] = \sum_i p_i \log_2 \frac{N}{n_i} = -\sum_i p_i \log_2 p_i
$$

สองสูตรนี้มีรูปร่างเหมือนกัน ทั้งคู่เป็นค่าคาดหมายของ Feedback Split เดียวกัน ต่างกันแค่คะแนนของแต่ละกลุ่ม คือขนาดของมัน หรือจำนวนครั้งที่หารครึ่งได้

ตัวอย่างเล็ก ๆ จะช่วยให้เห็นภาพ สมมติ Candidate 10 คำแบ่งเป็นกลุ่มขนาด 5, 3, 1 และ 1 โอกาสของแต่ละกลุ่มคือ 0.5, 0.3, 0.1 และ 0.1

```python
from math import log2

def expected_left(sizes):
    n = sum(sizes)
    return sum(c * c for c in sizes) / n

def expected_bits(sizes):
    n = sum(sizes)
    return sum(c / n * log2(n / c) for c in sizes)

expected_left([5, 3, 1, 1])   # 3.6
expected_bits([5, 3, 1, 1])   # 1.685
```

โดยเฉลี่ยเราคาดว่าจะเหลือ Candidate 3.6 คำ และ Guess นี้มีค่า 1.685 บิต <MarginNote>Solver ใช้สองสูตรเดียวกันนี้ เพียงแต่คำนวณกับทุกคำพร้อมกัน</MarginNote>

## สองวิธีอาจไม่ตรงกัน

ถ้าทั้งสองวัดการแบ่งเดียวกัน ทำไมต้องมีสองวิธี เพราะสองวิธีปฏิบัติต่อกลุ่มใหญ่ต่างกัน กลุ่มใหญ่ถูกนับเป็นกำลังสองในสูตรแรก จึงเสียหายมาก ส่วนในสูตรที่สองมันนับผ่านลอการิทึมเท่านั้น จึงเสียหายน้อยกว่า

สองวิธีนี้เลือกคำต่างกันจริง ๆ ในทั้ง Answer List Guess ที่มี Expected Information มากที่สุดคือ <Word>tarse</Word> คือ 5.947 บิต และเหลือ Candidate เฉลี่ย 66.0 คำ Guess ที่มี Expected Candidates น้อยที่สุดคือ <Word>roate</Word> เหลือ 60.4 คำ แต่ได้เพียง 5.883 บิต <Word>tarse</Word> แบ่งได้หลายกลุ่มกว่า คือ 147 เทียบกับ 126 แต่มีกลุ่มหนึ่งที่ใหญ่กว่า คือ 227 คำเทียบกับ 195 คำ

ไม่มีวิธีไหนผิด ทั้งสองคือคำตอบสองแบบของคำถามที่ว่า "การแบ่งที่ดีหน้าตาเป็นอย่างไร" ส่วนที่เหลือของ Series นี้จะสร้างเครื่องมือเพื่อลองทั้งสองแบบ Article ถัดไปแสดงวิธีหา Candidate และ Article หลังจากนั้นสร้าง Feedback Split สำหรับ Guess ใดก็ได้ แล้วแสดงตัวเลขทั้งสองแบบ
